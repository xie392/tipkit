# TipKit 高级插件实现计划（Unique ID → Emoji 完整版 → AI 集成）

按依赖与风险从低到高分三个阶段，每阶段结束跑 `pnpm type-check && pnpm test && pnpm build` 验证。所有新代码遵守现有分层铁律（extensions 只加 `tk-*` 语义类、依赖一律 `useEditorDeps()` 注入、视觉进 ui/themes、单文件 ≤500 行）。

## 阶段 1：Unique ID 扩展（地基，~1 天）

**新增** `packages/extensions/src/unique-id/unique-id.ts`：
- `Extension.create` + `addGlobalAttributes`：给指定节点类型加 `id` attr
- `addProseMirrorPlugins`：`appendTransaction` 中为无 id 的新建节点补 id；过滤协作/撤销等非事务噪声（对比 `tr.docChanged` 且新节点确实缺 id）
- Options：`types: string[]`（默认 paragraph、heading、blockquote、listItem 等块级）、`generateID?: () => string`（默认基于 `crypto.randomUUID` 的短 id）
- barrel：`src/index.ts` 导出；**不进** basic/advanced 集合（opt-in，避免改变现有文档 id 行为）
- 测试 `tests/nodes/unique-id.test.ts`：新建文档自动补 id、粘贴节点补 id、已有 id 不覆盖、配置自定义 generateID

## 阶段 2：Emoji 完整版（优化 + 新增，~2-3 天）

**优化现有**：
- 复用 `src/emoji/emoji-data.ts` 现有数据表；如缺短代码字段则补充 `shortcodes: string[]`
- `emoji-suggestion.tsx`（ui 包浮层）选中项从"纯插入文本"改为插入 emoji 节点（见下）

**新增** `packages/extensions/src/emoji/emoji-node.ts`：
- inline atom Node：attrs `{ name, shortcode, glyph }`，渲染 `<span class="tk-emoji" data-shortcode="...">😀</span>`，parseHTML 兼容纯文本回退
- Input Rule：输入 `:smile:` 自动替换为对应 emoji 节点（数据表里查 shortcode）
- Commands：`insertEmoji(name)`、`setEmojiSkin?`（数据表含肤色则做，否则砍掉保持简单）
- markdown 序列化：输出 `:smile:` 短代码（走现有 markdown 包的 serialize 规则）
- slash 菜单/i18n 无需新增文案（现有 suggestion 已覆盖入口）
- 测试：输入规则替换、序列化/反序列化 roundtrip、未知短代码不替换

## 阶段 3：AI 集成（新增，~1 周）

**core 层**（`packages/core/src/types.ts` + `context.tsx`）：
- `EditorDeps` 新增可选字段 `ai?: AIProvider`，类型：
  - `streamText(req: { prompt: string; instruction?: string; selection?: string; signal?: AbortSignal }): AsyncIterable<string>`
  - `translate?`、`simplify?` 等预设 action 只是 prompt 封装，核心只暴露 `streamText`（core 不含任何厂商 SDK）
- i18n 词典（zh/en）加 AI 相关 key（生成中、接受、放弃、重试等）

**extensions 层** `packages/extensions/src/ai/`：
- `ai-generation.ts`：`Extension.create`，commands：`aiGenerate(instruction)`（在光标处流式插入）、`aiRewrite(instruction)`（替换选区）、`aiAsk(instruction)`（结果插入为新块）；流式写入用单一 `dispatch` 节流（~100ms/帧），避免每 token 一次事务
- 预览/确认流：生成内容先进入临时状态（Decoration 高亮预览），用户"接受"才落为正式内容，"放弃"则丢弃——命令层实现，不依赖 UI
- 错误/中断：AbortController，失败可重试

**ui 层**（`@tipkit/ui`，仅布局）：
- `ai-menu/`：AI 浮层原语（触发按钮 + 指令输入 + 流式预览区 + 接受/放弃按钮组），flex/gap/z-index 布局，无颜色字体

**消费方装配**（demo）：
- `demo-editor.tsx`：deps 注入 mock `aiProvider`（本地 setTimeout 假流式，演示用）
- 文档：`apps/demo/src/content/docs/plugins-ai.mdx` + `.en.mdx`（表格行 + 小节），`docs-sidebar.tsx` 加分组项

**测试**：
- `tests/ai/ai-generation.test.ts`：用 fake AsyncIterable provider 测流式插入、rewrite 替换选区、abort 中断、接受/放弃状态清理
